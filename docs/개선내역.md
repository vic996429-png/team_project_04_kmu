# 개선 내역 — 4개 시제품 사이트 비교를 바탕으로

2026-11-26 기준. 이 저장소(A)를 기반으로 B·C·D의 장점을 옮기고 각 사이트의 단점을 없앴다. 비교 방법은 같은 가상 민원 5건 호출, axe-core, 화면 조작이다(외부 점검, 1회 측정).

| 출처 | 가져온 장점 | 반영 |
|---|---|---|
| A | 접수 후 흐름, 정책 소개, 접근성, 브랜드 | 그대로 유지 |
| B | 안내 챗봇, 「하지 않는 것」 명시, 1·2차 판단이 다르면 검토필요 | `/api/chat`과 챗봇 창, 민원 쓰기 화면에 「이 서비스가 하지 않는 것」 추가 |
| C | 근거 조문을 붙인 답, 판단 기록, 시도 기록 | 챗봇 답에 근거 문서·조문 표시, 담당자 화면의 AI 호출 순서 유지 |
| D | 시연 데이터 되돌리기, 판단 이력 | 이미 있어 유지 |

| 단점 | 조치 |
|---|---|
| A: AI가 꺼지면 위협 글이 「정상」 | 판단 못 하면 stage를 비워 「AI 미표시」로 담당자에게 전달(`unjudged: true`) |
| A: 표현 목록이 협박·비꼬는 말을 놓침 | 협박·모욕 표현 18개 추가, 일상 문장 오탐 테스트 |
| A: 챗봇 없음 | 문서 검색 + 선택적 AI 답변. 문서에 없으면 모른다고 답하고 감사담당관 연락처 안내 |
| C: 접근성 위반 | A의 색을 유지하고 챗봇도 axe 0건 확인 |
| D: 정상 글 오탐 | 목록에 일상 문장 회귀 테스트 추가 |

## 남은 과제

- 배포본에 `CLAUDE_API_KEY` 등 AI 키와 `LAW_OC` 등 공공 API 키를 Vercel 환경 변수로 넣어야 한다. 키가 없으면 AI 분류와 「시연 값」 표시는 그대로다.
- 표현 목록은 시제품용 소형 목록이다. 실제 도입에는 구청 검토가 필요하다.
